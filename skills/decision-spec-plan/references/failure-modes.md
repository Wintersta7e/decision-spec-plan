# Failure modes — each one happened, most more than once

Evidence is from one project run through this route three times (phases 2–4), stated anonymously.
Paste the relevant rules into briefs; cite the row as `failure-modes F<n>` when an agent pushes back
(a reconcile finding is also `F<n>`).

## Partition and authority

| # | Failure | Evidence | Rule |
|---|---|---|---|
| F1 | Agents partitioned by spec section invent two answers for one thing | **105** found by reconciliation (≈40 agents, by section) vs **1** (≈10 agents, by decision, after an arbiter settled the seams) — in two phases of one project; the agent counts differ too | Partition by decision while decisions are open; by file once made; by seam to reconcile |
| F2 | A partition by decision leaves the seams unsettled | 16 seams in one round, 17 blockers in the next; **11 of 16** were one ruling asserting a property of a neighbour's output the neighbour never promised | Always run a seam review before writing the arbiter; fence neighbours in the index ("may NOT decide") |
| F3 | A question framed for two rows gets two answers | "When does a verdict pay?" was split between a pricing row and a transitions row; the framing review caught it before dispatch | Framing review before dispatch; frame any shared question once, in the index |
| F4 | The arbiter is wrong | Plan and spec authors overturned the arbiter **six times** in one round, each correctly | Tell every agent to report disagreement; mark corrected rulings in place with the challenger named |
| F5 | A ruling rewritten in place while agents read it | A heading kept a withdrawn answer while its body carried the new one; **three plans** wrote the withdrawn id | Never rewrite a live ruling; append, mark, and quote rulings verbatim in messages |
| F6 | The index states something false and every agent inherits it | "Phase 1 recorded everything a split needs" (false — nothing reachable wrote the records); "an updater is open" (the user had ruled it out weeks earlier) | Agents are told to challenge their row's framing first; verify index claims against the tree before dispatch |

## Producers, gates and tests

| # | Failure | Evidence | Rule |
|---|---|---|---|
| F20 | A trait/seam gets its fake and never its production implementation | Five instances in phase 1; each compiled, passed against the fake, failed at assembly | Declare the seam and its production implementation in the same task |
| F21 | A producer with no production caller | **Six** producers in one phase ran only in tests behind all-green suites; one made an ungranted sweep close and pay every item | An unwired-producer audit before registering a phase; every producer names its caller; one criterion drives it through the production path |
| F22 | A bar written past its defect | A CI grep over gitignored paths; a gate asserting the wrong attribute so every motion clamp was inert; **an argv-only audit that passed while user config made the audited command delete a checked-out branch** | A test must exercise the shape the product actually has — including config and environment |
| F23 | A gate that scans nothing passes | Scans of zero files reported green | Every scanning check prints its count and fails at zero |
| F24 | A test that cannot fail | A test named for cross-language agreement asserted only one language | Prove a new test bites: revert the fix, watch it fail |
| F25 | A File-structure table hides missing tasks | **10 of 21** plans shipped a table and no tasks for the UI it promised | `scope_check.py`: every promised file is created by some task — a heuristic (a file named twice anywhere counts as implemented), so it catches a truncated plan, not a task that mentions a file without creating it |
| F26 | Acceptance checks with an owner and no implementing task | **41** found at once; a later phase whose project never ran `criteria_check.py` carried a registered check with no writing task to the edge of execution | Every plan names the task that creates each acceptance test file; `criteria_check.py --plans` checks every criterion reaches one — run it at the gate and record its exit status in the handoff |
| F27 | A producer reads *unreadable* as *absent* | A file that existed but could not be read was stored as missing and would have opened a "missing" item on a repository that had it; in another project an unreadable state file got the saved library overwritten with defaults | A producer distinguishes absent from unreadable before it creates, opens or overwrites anything |
| F28 | A manifest trimmed to keep a checker quiet | One manifest listed 50 of ~125 exports because the rest turned the collision checker red; the collisions it hid became rulings | Every name another plan consumes is in the manifest; widen the checker, never trim its input |
| F29 | The body changes and the bar does not | One round fixed a spec body and left five criteria asserting strings it had just deleted; a build made to pass them would have shipped a destructive control | A change to a value changes the criterion that tests it; a supersession lands with its code |
| F30 | A criterion a correct build cannot pass | One caught in a single plan round | Report it with file:line on both sides; never drop or weaken it |
| F31 | A gate piped into a truncator | A gate piped through `tail`/`head` returned the pipe's exit status and read green; one project now blocks the form with a hook | Never pipe a gate; chain gates with `&&`; every gate runs through `scripts/gate.py`, which streams the output and writes the `exit=` line itself |
| F70 | A green gate taken for a reviewed change | E: a finished lane's full gate was ALL GREEN 25/25 and its push was pre-authorized; a seven-sins review of it then found two new highs — a tag read with no byte cap and no dedup (1.01 GB read from a 61 KB crafted repository, measured; the core aborts on the allocation) and a migration that re-queued every finished history job while the job that re-runs them had no production caller, leaving a view blank until a manual rescan. The debate struck a first-proposed fix of each: wiring that job at startup would have turned the first high's crash into one at every launch, and the other fix used a git subcommand the project's read-only allowlist forbids. The push was held. J: a review before every push drew the user's overrule twice ("trigger at the very end"), and an announcement fell from 85M to 65M without them; the user ruled (2026-10-27) the sins run only on really large work, at a large phase's end, or when asked | At rung L the phase's last push, and any push the user asks a review of, needs a seven-sins verdict that covers it (`sins/lead.md`, code mode; `route_state.py --activate --sins on`, `off` after that push); `push_guard.py` checks its `reviewed=` / `base=` / `blocking=0` / `after=` stamp; a new high is fixed by a fresh group from the reproduction-amended recommendation, or waived by the user; over 30 commits the review runs per slice (F95) |
| F71 | A defect designed into a self-consistent spec | E: the second high above was written into its spec section and its plan, and the job that would have repaired it was an earlier phase's producer that never got a production caller (F21); the documents agreed, so reconciliation — which reads for contradictions and counts scope as noise — had nothing to report, and the lane's tests passed | At rung L, and at any rung when the user asks, the seven sins review the phase's spec sections and the code they change in Stage 3, beside the reconcilers (2026-10-28: on-ask alone lost this coverage); the lead rules both sets together in the plan index. At M the requirement-dimension table (F94) and the review prompts' N/A check stand in |

## Agent mechanics

| # | Failure | Evidence | Rule |
|---|---|---|---|
| F32 | One agent emitting N large items | ~30 items in one structured output returned `output_tokens: 2`, **twice** | Emit an index; fan out one agent per item; agents write files and return manifests |
| F33 | Replies truncated | Anything only in a ~4 KB reply was lost | Write the file first; reply short |
| F34 | Concurrent edits to one file | Several edits in one message raced on one snapshot and applied partially, silently | One file per message, or one full write |
| F35 | A document rewritten wholesale | A spec rewrite silently dropped two subsystems while the acceptance bar still tested them | Patch with anchored edits; never rewrite a document wholesale |
| F36 | Shared scratchpad | Parallel agents shared one scratchpad; a generic filename put one agent's commit message on another's commit | A private subdirectory per agent; messages on stdin |
| F37 | A second model's quota runs out mid-review | A cross-model review died two minutes in at its usage limit | SKILL.md (unavailable: Lead mechanics) |
| F38 | The session limit stops every background agent at once | In one plan round it cut every author's manifest and reply while the plans ended intact; a later round read the older "plans were truncated" record as fact | Check an artefact's end (fences, last task, criteria placed) before calling it truncated or complete; cite the newest record |
| F39 | Polling a background job by keyword | A wait loop exited at once because progress lines contained "completed" | Poll the job's state line |
| F40 | Ordering defects | A plan split across a boundary its dependency row could not express — six in one phase | Land the minimal forward-compatible piece and record it |
| F72 | A reply recorded before it arrived | A two-agent `dsp-deep` messaging probe (2026-10-14): told to send a challenge, end its turn and wait, the sender kept going, wrote an invented answer into its file and returned `pending: none`; the real answer arrived two seconds later with different text, and the agent then corrected itself. In run E a reviewer's return claimed two rejections its own report did not record | `sins/protocol.md`: after sending, end the turn; record a reply only once its message is in the conversation. `sins/lead.md`: every reproduction is recorded on both sides, and a mismatch goes to a claim-only verifier (F95) |
| F73 | Reviewer names reused across reviews | F: a second code review's reviewers went out under the bare sin names the first review's idle reviewers still held; the tool renamed the new ones (`wrath-2`), and a message to the bare name woke the old reviewer, which wrote into its closed report | `sins/lead.md`: each reviewer named `<sin>-<review name>`, all seven names in every prompt, messages only to those names; `TaskStop` the seven once the verdict is written |
| F45 | A cheaper tier drops whole items, not detail | Three roles replayed on `sonnet` against a same-input control: markers lost one ruling from all five files that carried it; a harvester missed an open question that became a spec cluster; a register fold named 38 of 45 moved criteria to the control's 44 — and one reply claimed a total it had not written | `prompts.md` header: the session's model and effort by default; Sonnet only where the role's row allows it, with a reason, the output checked against its inputs; a replay with a control settles a role for a project |
